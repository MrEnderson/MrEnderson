## Security boundary

Exactly **one** genuine, side-effecting `ToolAdapter` exists in this
codebase: `file.create_sandboxed` (create-only, no overwrite, sandboxed,
size-capped, UTF-8-text-only, extension-allowlisted). Every other
registered `ToolDefinition` (research.read, plan.create, artifact.draft,
mock.external_action, communication.send_email, content.publish,
resource.delete_external, finance.spend_money, system.install_software,
system.privileged_shell) is metadata only — attempting to execute any of
them fails closed with `ADAPTER_NOT_FOUND`. No shell, browser, desktop,
email, publishing, financial, install, admin, remote-control,
credential-management, self-modification, or autonomous-Git capability
exists anywhere. No live Anthropic/Tavily/network call is made by any
code path exercised in v0.1.3.1-.8.

## Known limitations (carried forward from v0.1.3.7, unchanged unless noted)

- Dispatch is strictly sequential — no parallel Action execution.
- `MODEL_CALLS`/`ESTIMATED_COST` budgets are opt-in (unconfigured =
  unlimited); `ACTION_ATTEMPTS`/`ESTIMATED_COST` are now enforced at the
  real pre-execution boundary as of v0.1.3.8 (previously a gap — see the
  v0.1.3.8 delivery report). `MODEL_CALLS` remains tested only through
  its reservation contract, since no Action makes a model call.
- No generic rollback/compensation framework.
- No parallel/distributed Action execution or multi-machine worker pool
  beyond the atomic single-file-SQLite claim primitives already proven.
- Concurrency guarantees are proven against a single SQLite file via real
  concurrent connections — not a distributed-database guarantee.
- "Durable + idempotent + reconciled" is NOT the same claim as
  mathematically guaranteed distributed exactly-once execution.

## Intentionally unsupported capabilities (by design, not oversight)

Shell/PowerShell/cmd/bash execution, browser automation, desktop
automation, email sending, social-media/web publishing, financial
transactions/purchases/cryptocurrency, software installation, privileged/
admin OS operations, remote-machine control, credential/secret
management, self-modification, autonomous Git operations, any second
genuine external `ToolAdapter`. None of these gained a registered
adapter at any point in v0.1.3.1-.8, and none is planned before an
explicit, separate authorization decision.
